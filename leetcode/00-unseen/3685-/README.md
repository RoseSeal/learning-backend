# 3685. 含上限元素的子序列和

记录：独立 · 未超时 · 首交未过

## 我的思考

**题意**：给定长度为 n 的数组 `nums` 和正整数 k。对每个 x ∈ [1, n]，把每个元素替换为 `min(nums[i], x)`，判断能否从替换后的数组中选出非空子序列，使其和恰好为 k。返回长度为 n 的布尔数组。

**约束**：1 ≤ n ≤ 4000，1 ≤ nums[i] ≤ n，1 ≤ k ≤ 4000。允许 O(nk) ≈ 1.6e7。

**思路**：
- 子序列和只与选了哪些值有关，与顺序无关，所以先用 `count[v]` 统计每个值的出现次数，用后缀和 `limCount[v]` 统计值 ≥ v 的元素个数。
- 限制为 x 时，元素分成两部分：
  - 值 ≤ x 的元素保持原值，用 0/1 背包（0/1 knapsack）维护可达和 `dp`；
  - 值 > x 的元素全部变成 x，共 `limCount[x] - count[x]` 个，只需枚举从中取 t 个，检查 `dp[k - t·x]` 是否可达。
- x 从小到大递增，每轮只把 `count[x]` 个值为 x 的元素加入背包，`dp` 增量维护。
- 提前终止：某一轮 `dp[k]` 为真，说明只用值 ≤ x 的元素就能凑出 k。这些元素在更大的 x 下不受影响，所以 x 及之后的答案全为 true。

## 卡点

- **偏移量写错（导致首交未过）**：原设计让 `dp` 落后一轮，处理 x 时 `dp` 只包含值 ≤ x−1 的元素。实现时把 `runDp(dp, x - 1, count[x - 1], k)` 误写成 `runDp(dp, x, count[x], k)`，属于手误。
- **复杂度退化未察觉（隐藏性能 bug）**：首个 AC 版本对受限部分复制一份 `dp` 再跑一次背包，即 `runDp(currLimDp, x, limCount[x], k)`。`limCount[x]` 可达 n 级别，最坏为 O(n²k)，约 6.4e10。当时看两处都是循环内的 `runDp`，以为开销相同，没有检查第二处的循环次数。LeetCode 测试集没有发现，是 review 时发现的。

## 关键点

- 受限部分的元素都等于 x，不需要再做一次背包，直接枚举取 t 个 x，检查 `dp[k - t·x]` 即可，t ≤ min(值 > x 的元素个数, k / x)。
- 改为「先把当前值加入 dp，再检查值 > x 的部分」后，不再需要让 `dp` 落后一轮，偏移错误从结构上消除。

## 复杂度

- 时间：背包部分合计 Σcount[x]·k = O(nk)；检查部分合计 Σk/x = O(k log n)。总计 O(nk)。
- 空间：O(n + k)。

## 注意

- 两次调用同一个函数时，要分别核对每次调用的循环次数，不能因为外形相同就认为代价相同。
- 提交前自造极值用例：所有元素都等于 n，k 取凑不出来的值。这类用例能暴露每轮跑满的最坏情况。
- 值 > x 的元素个数可直接写成 `limCount[x + 1]`（数组开到 n + 2），语义更直接。
- 删除未使用的 `currLimDp`。
