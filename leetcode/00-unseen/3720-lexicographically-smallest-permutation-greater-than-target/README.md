# 3720. 大于目标字符串的最小字典序排列

记录：独立 · 超时 · 首交通过

## 我的思考

**题意**：给定长度均为 n 的小写字符串 s 和 target，求 s 的一个排列，要求它严格大于 target，并且在所有这样的排列里字典序最小；不存在时返回空串。1 ≤ n ≤ 300。

**解法**：s 只关心字符计数，先压成 count[26]。答案的结构是：
- `[0, k)`：与 target 完全相同；
- 位置 k：剩余字符中大于 target[k] 的最小字符；
- `(k, n)`：剩余字符升序排列，与 target 无关。

从左往右扫描 target，维护「已经扣掉前缀 `[0, i)` 之后的 count」：
- 在位置 i，先检查剩余字符里是否有大于 target[i] 的字符，有就记 biggerIdx = i，并且一直覆盖，最后留下最大的可行位置；
- 再扣掉 target[i]，一旦变成负数，说明前缀凑不出来，break。

最后从原始 count 出发，按上面三段构造答案；biggerIdx = -1 时返回 ""。

## 卡点

- 最初的贪心是「每一位都取大于等于 target[i] 的最小字符，一旦取到严格大于，后面就升序」。反例：target 开头是几个小字符、后面全是大字符时，前面的位置必须提前放一个大字符。由此转向「只需要找一个分歧点 biggerIdx」。
- 想过二分 biggerIdx，配合 preCount 比对。后来发现可行性不单调：「前缀能凑出来」是单调的，「剩余字符里有大于 target[i] 的」不单调，两者合起来也不单调。于是改成线性扫描，preCount 也就不需要了。
- 想到线性解之后，看到 n = 300 又犹豫，怀疑这个范围是在暗示 O(n) 不可行。

## 关键点

- 把问题归结为「找一个分歧点 k」：k 之前和 target 相同，k 处严格大于，k 之后不再管 target。
- 可行性不单调，所以不能二分，只能线性扫描；扫描时增量维护 count，就不需要 preCount。

## 复杂度

- 时间 O(26n)，空间 O(26)。
- 输出本身就是 n 个字符，所以已经是最优。

## 注意

- **k 取最大的可行位置**，口述时漏掉了这个论证。设两个可行位置 i < j，以 j 为分歧点的答案在位置 i 上等于 target[i]，以 i 为分歧点的答案在位置 i 上大于 target[i]，所以 j 对应的答案更小。
- 数据范围只给复杂度的**上界**，n 小不能用来否定一个更快的解。解法对不对靠论证判断；论证不出来时，n = 300 正好提供一条退路：从后往前枚举 k，逐个 O(n) 验证，总共 O(n²) 稳过。
- 检查位置 i 时必须**先检查、后扣减**，这样 count 正好是扣掉前缀 `[0, i)` 之后的状态。
