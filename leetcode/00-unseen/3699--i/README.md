# 3699. 锯齿形数组的总数 I

记录：独立 · 未超时 · 首交通过

## 我的思考

题意：给定 n、l、r，统计长度为 n 的数组个数，要求每个元素取值在 [l, r] 内，相邻元素不相等，任意连续三个元素不能严格递增或严格递减。结果对 1e9+7 取模。

约束：3 ≤ n ≤ 2000，1 ≤ l < r ≤ 2000，记 m = r − l + 1 ≤ 2000。

思路：下一个数能怎么选，只取决于当前值 x 和下一步是向上还是向下。因此维护两个数组：
- `up[x]`：以 x 结尾、最后一步向上的数组个数；
- `down[x]`：以 x 结尾、最后一步向下的数组个数。

转移：
- `nextUp[x] = Σ_{y<x} down[y]`
- `nextDown[x] = Σ_{y>x} up[y]`

区间求和用前缀和加速，每轮 O(m)。数组里存的就是前缀和形式，取值时直接用 `down[x-1]` 和 `up[m-1] - up[x]`。

初始化相当于已经完成了长度为 2 之前的一轮，所以主循环跑 n − 1 轮，答案为 `up[m-1] + down[m-1]`，即两个前缀和数组各自的总和。

## 卡点

- 主循环一开始写成 `i < n`。原因是没有对齐初始化代表的长度和迭代轮数：初始化已经相当于推进了一轮，应该只跑 n − 1 轮。

## 关键点

- 状态是（当前值，最后一步的方向），只用当前值不够。
- 转移是一段区间和，用前缀和把每轮从 O(m²) 降到 O(m)。

## 复杂度

- 时间：O(n · m)，约 4×10⁶
- 空间：O(m)

## 注意

- `nextUp[x]` 一开始误写成 `down[x]`，正确的是 `down[x-1]`，因为要求严格小于 x 的前缀。把前缀和当状态存时，下标偏移容易写错。
- 另一种实现：数组存原始计数，转移时边扫边累加（running sum），可以避免下标偏移。
- 另一种思路：方向由第一步和奇偶性决定，而且可以把值 v 镜像成 m−1−v，所以答案 = 2 × 第一步向上的数组个数，只需维护一个数组。
