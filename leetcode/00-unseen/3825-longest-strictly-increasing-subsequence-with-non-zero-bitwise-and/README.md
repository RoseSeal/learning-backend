# 3825. Longest Strictly Increasing Subsequence With Non-Zero Bitwise AND

记录：H1 · 超时 · 首交通过

## 我的思考

题意：给定整数数组 nums，求最长严格递增子序列（subsequence）的长度，要求该子序列所有元素按位与（bitwise AND）的结果非零。

约束：1 <= n <= 1e5，0 <= nums[i] <= 1e9。

思考过程：
- 看到 AND 后第一反应是按位处理，但看到 nums[i] <= 1e9 时误以为位数太多，于是放弃了这个方向。
- 尝试枚举所有递增子序列逐个验证：子序列数量太多，不可行。
- 尝试寻找前缀的"断点"：由 a&b != 0 且 a&c != 0，推不出 b&c 的情况，也推不出 a&b&c 的情况，这条路走不通。
- 提示后回到按位的思路：AND 非零，等价于存在某一个 bit 在所有元素中都为 1。
- 问题因此转化为：对每个 bit，只保留该位为 1 的元素，在这些元素上求最长严格递增子序列（LIS，Longest Increasing Subsequence），最后对所有 bit 的结果取最大值。
- 最初想用单调栈维护递增序列，把栈的最大高度当作答案。这个做法被反例否定：弹栈会丢掉之后可能用到的前缀。之后改用 tails 数组加二分查找（binary search）。

## 卡点

- 约束映射（G1）：把"值域大"误认为"位数多"。实际上 1e9 < 2^30，只有 30 位。这个误判导致正确方向被排除，前期因此浪费约 25min。
- 求 LIS 时误用单调栈：单调栈只能维护一条递增链，一旦弹栈就丢失了其他候选前缀，所以不能求 LIS。
- 当时不认识 LIS 这个缩写。题 300 以前做过，但这次提示出现得太早，没来得及检验能否自己回忆起 O(n log n) 解法。

## 关键点

- 多个数的 AND 非零 ⇔ 存在一个公共 bit 在所有数中都为 1。于是"整体 AND 的约束"可以拆成"逐位过滤"：每个 bit 各做一次过滤后的子问题。
- 位数只有 log2(值域) ≈ 30。值域越大，按位拆分反而越划算。
- LIS 的 O(n log n) 解法：tails[k] 记录"长度为 k+1 的递增子序列的最小结尾值"。对每个新元素，二分找到位置后覆盖或追加。

## 复杂度

- 时间：O(30 · n log n)
- 空间：O(n)

## 注意

- 求严格递增时，二分找第一个 >= x 的位置（lower_bound）；如果题目是非严格递增，则改为找第一个 > x 的位置（upper_bound）。
- tails 数组中存的是结尾值，不是下标。
- 1e9 < 2^30，只需枚举 bit 0..29。
- tails 数组可以在各个 bit 之间复用：每轮把 len 重置为 0 即可，不必重新分配数组。
