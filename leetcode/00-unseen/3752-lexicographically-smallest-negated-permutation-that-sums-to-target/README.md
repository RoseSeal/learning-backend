# 3752. Lexicographically Smallest Negated Permutation that Sums to Target

记录：H2 · 未超时 · 首交未过

## 我的思考

题意：给定 n 和 target，构造一个长度为 n 的数组，要求所有元素的绝对值恰好是 1～n 的一个排列（每个数可以取正号或负号，顺序任意），数组之和等于 target。返回字典序最小的这样的数组；不存在则返回空数组。

约束：n ≤ 1e5，|target| ≤ 1e10。

思路：
- 初始时所有数都取正号，总和为 S = n(n+1)/2。每把一个数 i 翻成负号，总和减少 2i。
- 从大到小遍历 i：如果 sum − 2i ≥ target，就把 i 翻成负号。
- 遍历结束后若 sum ≠ target，返回空数组。
- 否则，负数按从小到大放在前面（也就是按绝对值从大到小，正好是选取的顺序），剩下的正数按从小到大放在后面。

## 卡点

- 首次提交在大输入上出错，当时判断不了是代码有 bug 还是解法本身有纰漏。实际原因是溢出（见「注意」）。
- 能想到贪心，但说不清它为什么一定能把总和凑到恰好等于 target。

## 关键点

- 子集和覆盖：1～k 中每个数最多取一次，能凑出 [0, k(k+1)/2] 里的任意整数。归纳证明：不选 k 能凑出 [0, T_{k−1}]，选 k 能凑出 [k, T_k]，由于 k ≤ T_{k−1} + 1，两个区间之间没有空隙。
- 问题可以转化为：从 1～n 中选一个子集取负号，子集之和要等于 D = (S − target)/2。条件 sum − 2i ≥ target 等价于 i ≤ 剩余的 D。
- 贪心的正确性：
  - 可行性：不变式为处理 i 之前，剩余 D ≤ i(i+1)/2。所以只要 i ≤ D 就可以放心选，剩下的部分一定还能凑出来。
  - 最优性：数组第一个元素是 −max(负数集合)，所以选上的最大数越大越好；之后每一位用同样的方式归纳。

## 复杂度

时间 O(n)，空间 O(n)。

## 注意

- `long sum = n * (n + 1) / 2;` 会溢出：右边先按 int 算完才赋给 long。要写成 `(long) n * (n + 1) / 2`。
- 出错后用对拍来区分：小规模用暴力解比对，结果都一致就说明是实现问题（溢出、超时、越界），不是算法问题。
