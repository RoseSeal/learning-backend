# 3714. Longest Balanced Substring II

记录：独立 · 未超时 · 首交未过

## 我的思考

题意：字符串 s 只含 'a'、'b'、'c'。如果一个子串中出现的每种字符次数都相同，就称它为平衡子串。求最长平衡子串的长度。1 ≤ n ≤ 1e5。周赛 Q3，rating 2202。

按子串中出现的字符种类数分三种情况，最后取最大值：

- 三种字符都出现：维护前缀计数 (a, b, c)，三个数都减去最小值后编码成 long 作 key。HashMap 只记录每个 key 第一次出现的下标，每到一个位置就用当前下标减去它，更新答案。
- 只出现两种字符：把第三种字符当作排除字符，分别跑三遍。key = countOne - countTwo + n，用 int[2n+1] 记录首次出现的位置。遇到排除字符时，计数清零，map[n] = i，同时把 lastInvalidIdx 记为 i。查询时只有 map[key] >= lastInvalidIdx 才算有效，相当于懒删除，不需要真正清空数组。
- 只出现一种字符：求最长的同字符连续段。

三种情况有重叠，但题目求的是最大长度，所以重叠不影响结果。

## 卡点

- 读错题：一开始以为三种字符都必须出现，先写出了三者相等的版本，之后才发现另外两种情况也算平衡。这一版最终用上了，但读错题让我犹豫：分三类讨论是不是因为先写了这一版才被带偏的？
- 遇到排除字符需要重置时，忘了把 countOne、countTwo 也清零，靠打 log 才找出来。
- 重置的代价导致超时：
  - 用 map.clear() 重置会超时。
  - 加 needRestart 标记、推迟到下一个非排除字符再 clear，在 abcabc 这类输入上照样频繁 clear。
  - 改成 int[2n+1] 配合 Arrays.fill，仍然超时。
  - 改成 new HashMap<>() 后通过。最后发现根本不用重置，用合法下标范围做懒删除就行。

## 关键点

- 分三类讨论是题目定义本身决定的：子串是否平衡取决于它包含哪些字符，字符集合不同，就没法共用同一张哈希表，所以必须分类。
- HashMap.clear() 会遍历整个 table，容量不会缩回去，代价是 O(capacity) 而不是 O(size)。
- 容器要反复重置时，每次重置的代价应该与上次重置之后写入的量成正比，而不是与容器大小成正比。可选做法：直接 new 一个新容器；用段起点做懒删除；只清理写过的 key。

## 复杂度

- 时间：O(n)，其中 HashMap 部分是期望 O(1)。
- 空间：O(n)。

## 注意

- 动手前先用样例核对题意：样例 "aba" → 2 就能直接推翻「三种字符都必须出现」的理解。
- 提交前把重置操作的代价单独算进复杂度。
- 另一种写法：枚举出现的字符集合 S（用 mask 表示），key 取「S 内字符的计数差 + S 外字符的原始前缀计数」。S 外的字符在子串中出现 0 次，等价于它们的前缀计数在子串两端相等。这样一个 solve(mask) 就能覆盖所有情况，不需要截断或重置。
