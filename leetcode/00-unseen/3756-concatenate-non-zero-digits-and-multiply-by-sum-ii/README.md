# 3756. 连接非零数字并乘以其数字和 II

记录：H1 · 超时 · 首交未过

## 我的思考

题意：给定只含数字的字符串 s 和若干查询 [l, r]。每个查询取子串 s[l..r]，把其中的非零数字按原顺序拼成整数 x（没有非零数字时 x = 0），sum 为 x 的数字和，答案为 x · sum mod 1e9+7。
约束：|s| ≤ 1e5，查询数 ≤ 1e5。

- sum 部分直接用数字和的前缀和。
- 难点在 x。直接把 s 转成整数，数字太大。每个查询现场拼一遍是 O(mn) = 1e10，会超时。
- 由此得到目标：用不超过 O(n log n) 的预处理，做到 O(1) 取出任意区间对应的大整数（取模后的值）。
- 用前缀存储：prefix[k] 是前 k 个非零数字拼成的数 mod M。下标按非零数字的个数编号，零在建表时就跳过。cnt[i] 是前 i 个字符中非零数字的个数。
- 递推式：
  1. a mod M = c1
  2. (a·10 + b) mod M = c2
  3. ((a·10 + b)·10 + c) mod M = c3
  要求 [b, c] 这一段的值，就是用 c3 减去 a 的贡献，而 a 的贡献是 c1 · 100 mod M。
- 推广：x(l..r) = prefix[pr] − prefix[pl] · 10^(pr−pl)，其中 pl = cnt[l]，pr = cnt[r+1]，另开一个数组预处理 10^k mod M。
- 区间内没有非零数字时 pr = pl，x 自然等于 0，不需要特判。

## 卡点

- 推到 c1 · 10^k 时，以为要对每个 c 都预存 n 种权位，复杂度变成 O(n²)。其实知道 (a mod M) · 10^k mod M 可以交换顺序，但推导时没反应过来，看到公式才想到把 10^k mod M 单独存成一个数组。
- off-by-one 卡了很久。同一个函数里混用了两套下标约定：preSum 用"前 i 个"（左闭右开），非零计数数组用"s[0..i] 中的个数"（闭区间）。结果写出了 max(0, l-1) 补丁，长度还多加了 1。调试时打印了 pl、pr，但手边没有手算的正确值做对照。

## 关键点

- 本质是字符串哈希（prefix hash）：区间值 = pre[r+1] − pre[l] · base^len，这里 base = 10，序列是去掉零之后的非零数字。
- 变量分离：要存的东西是两个独立量的乘积 f(c) · g(k) 时，拆成两张一维表，查询时再相乘。推出预处理要 O(n²) 或要二维表时，先检查能不能拆。
- 前缀类数组统一用"前 i 个"的定义，长度为 n+1，查询 [l, r] 一律写 f(r+1) − f(l)，长度就是两者之差，不需要 +1。

## 复杂度

时间 O(n + q)，空间 O(n)。

## 注意

- 减法取模要先加 M：(prefix[pr] − prefix[pl] · pow10 % M + M) % M。
- 需要写 max(0, …) 或 if (l == 0) 这类特判时，先回头检查数组定义是否统一。
- 提交前用最小样例手算 pl、pr：l = 0、l = r、包含前导零、全部是零。
