# 3670. 没有公共位的整数最大乘积

记录：H1 · 超时 · 首交通过

## 我的思考

题意：给定数组 nums，找两个不同下标 i、j，使 nums[i] 与 nums[j] 没有公共置位（即 `nums[i] & nums[j] == 0`，同一位都为 0 是允许的），求最大乘积；不存在则返回 0。约束：`2 <= n <= 1e5`，`1 <= nums[i] <= 1e6`。

1. 最初考虑二进制 Trie（字典树）：对每个 x，在 Trie 中查找与 x 无公共位的最大值。
2. 发现 Trie 查询不能贪心：x 某位为 0 时优先走 1 分支，但该分支下可能没有合法终点，需要回溯。考虑过直接按「右-根-左」做 DFS（深度优先遍历），第一个合法叶子即为答案，但无法确定复杂度是否可接受。
3. 转化问题：对每个 x，求 nums 中满足 `y & x == 0` 的最大 y，需要 O(1) 或 O(log) 的单次查询代价。
4. 意识到值域 1e6 < 2^20，2^20 个状态可以直接开数组。
5. 定义 `map[x]`：nums 中在 x 的所有置位上都为 0 的最大值。答案为 `max(num * map[num])`。
6. 填表：
   - 观察：`map[x] >= map[x | (1 << b)]`，b 为 x 中为 0 的某一位（限制越多，候选集越小）。
   - 基础值：恰好以 `full ^ num` 为限制时，num 本身是候选，`map[full ^ num] = num`。
   - 转移：`map[x] = max(基础值, max_b map[x | (1 << b)])`。
   - 顺序：`x | (1 << b) > x`，因此 x 从 full 递减遍历。

## 卡点

- 复杂度预算只按 n 写成「n 或 nlogn」，没有从值域 1e6 ≈ 2^20 推出「值域可作为状态」，在 Trie 修补与是否切换方法之间犹豫约 25 min。
- `map` 的转移关系推导约 20 min：对位运算上相对抽象的依赖关系（掩码与「多一位」掩码之间的关系）思考吃力。
- Trie 模版忘记怎么写（草稿中循环变量 m 与 mask 混用，按位与的结果未归一化为 0/1）。

## 关键点

- 值域小（≤ 2^20）时，把值本身当作状态，在全部掩码上计算。
- 状态定义：`map[x]` = 与 x 无公共位的最大值；查询时直接取 `map[num]`。
- 转移只需要从「多一个置位」的掩码转移，加上基础值 `map[full ^ num] = num`。
- 该技巧即 SOS DP（Sum over Subsets，子集/超集 DP）。

## 复杂度

- 时间：O(n + d · 2^d)，d ≤ 20，约 2e7。
- 空间：O(2^d)，约 4MB。

## 注意

- Java 中 `~num` 为负数，不能直接作下标，需写成 `full ^ num` 或 `~num & full`，其中 `full = (1 << d) - 1`。
- `full ^ num` 是单射，基础值可直接赋值，无需取 max。
- `num >= 1`，故 `num & num != 0`，`map[num]` 不会取到自身；重复值不会被误配。
- 乘积用 `1L * num * map[num]` 防止 int 溢出。
- 无合法配对时 `map[num]` 为默认值 0，乘积为 0，与题目要求一致。
- 二进制 Trie 查询在「可选两边」的位上不能贪心，回溯后复杂度无法保证。
