# 3733. 完成所有送货任务的最少时间

记录：独立 · 超时 · 首交未过

## 我的思考

题意：两架无人机分别要送 d0、d1 次货，每次送货占 1 小时，同一小时只能有一架在送。无人机 i 在 ri 的倍数小时充电，这一小时不能送货。求送完所有货的最少小时数。约束：di ≤ 1e9，2 ≤ ri ≤ 3e4。

复杂度推导：对 d 线性不可行；按周期 lcm 处理，lcm 最大约 9e8，逐小时扫最后一个周期也不可行，所以需要对数级的做法。

思路演进：
1. 以 L = lcm(r0, r1) 为周期。周期内的小时分四类：只有 0 能送、只有 1 能送、两架都能送、两架都在充电（第 L 小时）。
2. 用三个条件求出最少需要几个完整周期：d0 ≤ 0 的专属小时 + 共享小时；d1 ≤ 1 的专属小时 + 共享小时；d0 + d1 ≤ 总可用小时。
3. 前 prev 个周期里的共享小时合并成一个池子，两架先各自用专属小时抵扣需求，剩下的需求从池子里取，这样剩余量就是确定的。然后在最后一个周期里二分，二分时状态跟着 begin 一起累加。
4. AC 后改写：判定函数直接对任意时刻 T 计数，在 [(total−1)·L, total·L] 上做无状态二分。
5. 最终版：去掉周期计算，直接在 [0, 2(d0+d1)] 上二分 T，判定条件为：
   - T − T/r0 ≥ d0
   - T − T/r1 ≥ d1
   - T − T/lcm ≥ d0 + d1

## 卡点

- 按"完整周期 + 最后一个周期"拆分后，进入最后一个周期时 d0、d1 各剩多少不确定：前面的共享小时怎么分，会影响剩余量。

## 关键点

- 共享小时可以随意分给任一架，所以合并成一个池子即可：max(0, d0 − 专属0) + max(0, d1 − 专属1) ≤ 共享。这一个式子和三个不等式等价，并且本身就是一个可行的构造，充分性由此成立。
- 判定函数一旦能对任意 T 计算，按周期拆分就多余了。它只能把二分轮数从约 32 减到约 30，却多出一段代码和一个需要论证的前提。

## 复杂度

- 时间 O(log(d0 + d1) + log r)
- 空间 O(1)

## 注意

- 首交因溢出未过：d0 + d1 最大 2e9，超过 int 上限；prev 乘任何系数都会溢出。所有和 d 相加或相乘的量一律用 long。
- 把二分从 end 改成 mid 时只改了一半：getAvailable 调用和 currRest 里都有 end，要全部检查一遍。
- 上界 2(d0 + d1) 成立的原因：ri ≥ 2 且 lcm ≥ 2，到时刻 2S 时每个条件左边都 ≥ S。取 r = [2, 2] 时上界是紧的。
