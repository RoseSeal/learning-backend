# 3816. Lexicographically Smallest String After Deleting Duplicate Characters

记录：独立 · 未超时 · 首交通过

## 我的思考

题意：给定一个只含小写字母的字符串，可以任意删除字符，但每种字符至少保留一个。求字典序最小的结果（前缀相同时，较短者更优）。

约束：1 <= s.length <= 10^5 → 需要 O(n) 或 O(n log n)。

思路：单调栈贪心（monotonic stack greedy）。

- 用 `count` 实时维护每种字符尚未删除的数量（栈内 + 未处理的后缀），`count > 1` 即栈顶可删。
- 高位严格支配低位。栈顶 top 可删时有两个选择：删除，则该位由后续顶替上来的字符确定；保留，则该位确定为 top。
- 当且仅当顶替字符严格小于 top 时才删除。如果后续能顶替一个更小的字符，保留 top 得到的结果严格更差。
- 相等时不删，先入栈。如果之后来了更小的字符，相等的那批会被连着一起弹掉，相当于"相等时看后续有没有更小的"。
- 结尾处理：末尾的可删字符一律删掉，因为删后得到原串的真前缀，严格更优。等价于在末尾补一个比 'a' 还小的哨兵。

## 关键点

- 弹栈条件：`count[top] > 1 && c < top`，严格小于。
- 相等入栈不弹，例如 "aab" 的答案是 "aab" 而非 "ab"。
- 末尾修剪 ⇔ 哨兵 `'a' - 1` 统一进主循环。

## 复杂度

- 时间：O(n)，每个字符最多入栈、出栈各一次。
- 空间：O(n) 栈 + O(26) 计数。

## 注意

- 一遍扫描足够的依据：`count` 只减不增，所以栈中字符现在可删，那么它当初被后续字符比较时也可删。因此最终栈中任意相邻对 (x, y)，只要 x 可删，就有 x ≤ y，不存在"回头再删"的机会。面试被问"为什么一遍就够"时要主动说出这句。
- 和 316 的区别：316 要求每个字符恰好保留一次，需要维护 inStack；本题是至少保留一次，并且有"更短者更优"规则。和 1673 / 402 同骨架。
- 哨兵写法：`i < n ? s.charAt(i) : 'a' - 1` 能赋给 char，是因为 `'a' - 1` 是 char 范围内的编译期常量（JLS §15.25）。白板上写成 `(char) ('a' - 1)` 更稳。
- 面试讲解时保留单独的末尾判定，"严格更小顶替"和"更短前缀更优"分开讲；讲完再补一句可以用哨兵合并。
