# 3710. Maximum Partition Factor

记录：H2 · 超时 · 首交未过

## 我的思考

**题意**：平面上有 n 个点，要分成恰好两个非空组。一种划分的划分因子 = 两组所有组内点对中最小的曼哈顿距离（只有 1 个点的组没有点对，不参与取最小）。求所有划分中划分因子的最大值。n = 2 时答案为 0。

**约束**：2 ≤ n ≤ 500，坐标范围 ±1e8（距离最大 4e8，int 放得下）。

**思路过程**：

1. 先试贪心：按距离从小到大取点对 (i, j)，比较"i 放 A、j 放 B"和"反过来"两种放法哪个更好。后来发现这种放法只看已经放下的点，不能向后考虑，出错了也没法改，放弃。
2. 不提前确定放法：把距离最小的点对视为"必须异组"的约束。用 A(0,0)、B(0,2)、C(1,1) 三点两两距离都是 2 的例子，看出这些约束构成一张图，三个点两两必须异组是不可能的，答案就确定是 2。
3. 由此得到：按距离从小到大加"必须异组"的边，第一次出现"两点已经必须同组却又要求异组"时，这条边的距离就是答案。
4. 一开始想对每条新边从 i 出发 BFS，判断 i 到 j 路径长度的奇偶性。觉得会超时，改为只维护连通性和奇偶信息。
5. 实现：n×n 矩阵记录任意两点的关系（未连通 / 同组 / 异组）。合并两个连通块时，对所有跨块点对按 `rel(x,i) ⊕ 1 ⊕ rel(j,y)` 赋值。
6. 写完才发现"只维护连通性和奇偶"其实就是带权（奇偶）并查集。

## 卡点

- 起手用了贪心放置（G3），后来自己发现不能纠错就放弃了，没有反复修补。
- 判断"BFS 会超时"时没有计算。实际上只保留合并连通块的边构成一片森林，一次 BFS 是 O(n)，总共 O(n³) ≈ 1.25e8，大概率能过（G1）。
- 奇偶点集的更新规则写了两遍才写对。
- 后半段在 union 怎么实现上卡了很久：一直在点对层面维护关系，没有想起带权并查集（399 做过乘法权的版本）。
- 动手前一直没写复杂度估算那一行（G1）。

## 关键点

- 等价转化：划分因子 ≥ D ⇔ 距离 < D 的所有边构成的图可以二染色。所以答案 = 按距离从小到大加边时，第一次出现奇环的那条边的距离。
- 只需要维护连通性和奇偶，用奇偶并查集：
  - `p[x]` 表示 x 与父节点是否异色；`find` 时路径压缩并累计异或：`p[x] ^= p[parent[x]]`，**之后**再改 `parent[x]`。
  - 同根两点的关系：`p[x] ⊕ p[y]`。
  - 合并约束 rel(x,y)=d：`p[rx] = p[x] ⊕ p[y] ⊕ d`（沿 x→rx→ry←y 路径合成）。
- 带权并查集的抽象：边上可以带一个**能沿路径合成**的量（399 是乘法，本题是异或）。每个点只存到父节点的关系，合并时只设根之间一条边的权。

## 复杂度

- 本次实现：时间 O(n² log n)，瓶颈在边排序（Map 去重 + PQ，最坏 K ≈ n²/2 个不同距离）；union 合计 O(n²)。空间 O(n²)。
- 奇偶并查集：时间不变（仍然是排序瓶颈），并查集部分空间 O(n)。
- 另一种做法：二分答案 D + 对距离 < D 的边 BFS 二染色，O(n² log C)。

## 注意

- 首交未过：状态编码从"0 未连通、1 奇、2 偶"改成对调 0 和 2 时，union 里漏改了一处（G4）。状态用具名常量写，改编码时全局搜索所有用到的地方；提交前用 ABC 三点用例手跑一遍（G2）。
- n = 2 时永远不会出现冲突，循环结束后要 `return 0`。
- 按距离分组（Map + PQ）只在距离大量重复时有收益，最坏情况和直接排序同阶。默认写成 `int[]{dist,i,j}` 或 `long` 编码后直接排序。
- 判重时优先用下标或基本类型编码，不要自定义 `equals/hashCode`，也不要往 `Set` 里放 `int[]`（G5）。
