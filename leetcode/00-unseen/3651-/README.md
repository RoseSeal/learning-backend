# 3651. 带传送的最小路径成本

记录：H2 · 超时 · 首交通过 · 模拟

## 我的思考

给定一个 m×n 的矩阵，从左上角到右下角，普通移动只能向右或向下，代价为目标格子的值；也可以向任意值不大于当前格子的格子传送，代价为 0，最多传送 k 次。求最小总代价。m,n <= 80，k <= 10。

一开始考虑 DP，但发现传送可能导致格子之间存在环，因此考虑 Dijkstra。进一步思考，按照传送次数增加一个状态维度，仍然可以使用 DP。

定义 dp[i][j] 为最多使用 x 次传送到达格子 (i,j) 的最小代价。初始化时执行一次普通 DP，之后每轮迭代分为两个阶段：
1. 根据上一轮的 DP 结果，执行一次传送转移。
2. 按照从左上到右下的顺序执行普通 DP，传播传送带来的收益。

最初考虑预处理每个格子可以传送到的所有格子，但每轮转移需要 O((mn)^2)，存在超时风险。

进一步观察，传送的本质是查询所有 grid 值不小于当前格子的格子中，最小的 DP 值。因此可以将所有格子按照 grid 值降序排序，遍历时维护前缀最小代价。同值格子需要先整体求最小值，再统一更新。

传送转移可以直接原地更新，因为已经更新的格子不会再次被读取，且更新后的值不会小于当前维护的前缀最小值。

如果某轮传送没有产生任何代价下降，可以直接结束迭代。

## 卡点

- 最初认为格子之间存在环就无法使用 DP，没有立即想到按照传送次数分层。
- 长时间停留在平方复杂度的传送转移上，没有及时从目标格子的角度重新描述转移所需要的信息。
- DP 使用 1-based 下标，而 grid 和传送坐标使用 0-based 下标，导致传送阶段的 DP 访问全部偏移了一位。
- doJump 返回 true 表示发生了有效更新，但调用方的提前退出条件写反。两个 bug 叠加，调试 30min 未能独立定位。

## 关键点

- 原始节点之间存在环，不代表扩展后的状态之间也存在环。对于次数受限的操作，可以考虑将操作次数作为 DP 的一个维度，分层处理。
- 优化重复转移时，不仅要考虑如何快速枚举合法来源，还要明确究竟需要从这些来源中获取什么信息。本题只需要最小代价，而不需要具体的传送来源集合。
- 当不同查询的合法来源集合具有包含关系时，可以考虑排序后维护前缀或后缀聚合信息，避免重复计算。
- 将传送转移与普通移动分离，使每轮传送之后只需要一次普通 DP 扫描。

## 复杂度

- 时间复杂度：O(mn log(mn) + kmn)
- 空间复杂度：O(mn)

## 注意

- 多个方法、多个数组共同操作同一逻辑对象时，优先统一坐标系统。不要为了简化局部边界处理而增加全局实现复杂度。
- 布尔返回值应具有明确的语义，调用时可以使用 changed 等变量，避免判断条件写反。
- 多阶段算法出现 bug 时，分别验证各阶段的输入、输出及不变量，不要反复推演整个算法。例如本题可以构造所有格子值相等的 2×2 矩阵，单独验证一次传送后所有有效 DP 值是否均为 0。
