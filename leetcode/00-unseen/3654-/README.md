# 3654. 删除可整除和后的最小数组和

记录：独立 · 未超时 · 首交通过

## 我的思考

题意：给定整数数组 nums 和整数 k。可以多次选择和能被 k 整除的连续子数组并删除，删除后剩余元素补位。求经过任意次删除后，nums 的最小可能和。

约束：1 <= n <= 1e5，1 <= nums[i] <= 1e6，1 <= k <= 1e5。时间复杂度需要 O(n) 或 O(n log n)。

1. 直接贪心，遇到能被 k 整除的段就删。反例：[5,1,11]，k = 3。删 5+1 剩 11，删 1+11 剩 5，所以先删到的段不一定最优，直接贪心不可行。
2. 枚举所有可删子数组：以 nums[i] 为删除终点，需要找满足 pre[j] ≡ pre[i+1] (mod k) 的 j，本质上是两数之和问题，用前缀和加哈希表可以 O(n) 枚举。
3. 把可删子数组按和排序，优先删最大的。反例：[97,1,1,1,194,1,1,1,99,99]，k = 100。和最大的是中间的 [1,1,1,194,1,1,1]（和为 200），删掉后剩 295；删 [97,1,1,1] 和 [1,1,99,99] 剩 194。不可行。
4. 把子数组看成图的节点，在互不重叠的子数组中选总和最大的一组，不好做。
5. 换个角度：这些子数组本质上是在原数组上选择是否删除的若干连续块，正好是线性 DP 的结构。
   - dp[i]：前 i 个元素处理后的最小和。
   - 转移：dp[i+1] = min(dp[i] + nums[i], min{ dp[j] : pre[j] ≡ pre[i+1] (mod k) })。
   - 按余数维护 dp 最小的那个下标，每步 O(1)。

## 卡点

- 两次尝试贪心（直接删、按子数组和排序删）都被反例否定；建图选不重叠区间的想法也没推进下去，之后才转向 DP。

## 关键点

- 余数相同的两个前缀之间那一段，和能被 k 整除（同余前缀和，可类比两数之和）。
- 把所有删除操作看成原数组上若干互不相交的连续块，这样就变成线性 DP。

## 复杂度

- 时间 O(n + k)
- 空间 O(n + k)

## 注意

- 承重论证要说出来：多步删除（包括补位后拼出的新子数组）的结果，等价于在原数组上选若干互不相交的段，每段的和都 ≡ 0 (mod k)。原因是：一个极大被删块是多次删除的并集，每次删掉的和都 ≡ 0，所以整块的和也 ≡ 0；反过来，任何和 ≡ 0 的块都可以一次删掉。
- 转移必须和 dp[i] + nums[i] 取 min，不能写成「找得到 j 就取 dp[j]，找不到才取 dp[i] + nums[i]」。
- 同一余数可能对应多个 j，要取 dp 最小的那个，所以 map 存的是 argmin，不是最近一次出现的下标。
- 前缀和最大约 1e11，必须用 long。
- 可读性改进：用 long[] best 直接存每个余数对应的最小 dp（初始为 Long.MAX_VALUE，best[0] = 0），这样不需要 -1 哨兵和 j == -1 分支，preSum 数组和 dp 数组也可以换成滚动变量。
