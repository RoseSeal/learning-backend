## 复盘笔记

# 3900

## 题意

仅含 '0'、'1' 的字符串 s。最多交换任意两个字符一次，然后选一个 0 与 1 数量相等的子串，求最大长度。

## 我的思考

遍历字符串，记录当前diff，diff为已经遍历的0与1的差值。
使用map存储历史diff和对应的下标。
对于当前diff，寻找：
key == diff
key == diff + 2
key == diff - 2
对应的下标。
对于后两者，还需要单独判断下标之外是否有足够的0或者1供交换。
可以记录最早最晚出现的第一个0和1，并判断left和rigth范围来判断。
然后记录全局最大ans即可。
同时，我也注意到有一个bug，同一个key，更早的下标不一定支配更晚的。
因为更早的下标会出现1或者0不够，无法替换的情况，而更晚的下标则可能可以。
这里我想到两种方案。
1是把map改成Map<Integer, List<Integer>> 记录下标集合，并且遍历顺序自然保证了下标入表顺序为从小到大，我只需要顺序遍历List，找到第一个满足要求的下标即可（key == diff时无条件满足，后两者则有对应规则）退出遍历。
这是最粗暴的，有不少优化空间，比如都无足够的0或1，下标更小的支配更大的。都有足够的0或者1，下标更小的支配更大的。
2是改进，改成两个表，
一个表无条件记录。
第二个表记录前面有0的diff
第三个表记录前面有1的diff
当key == diff，或者需要0，但curr后面有0，或者需要1但curr后面有1，时查询表1。
后两个对应使用。

我实现的花了不少时间，思路立刻有，但是实现感觉好麻烦，最后写成这样。
我发现这题其实还是暴露了问题，思路其实很快，几乎立刻就得出了。但是实现好慢，好多off-by-one要考虑，而且各种条件也需要斟酌，但其实还好，实现30min，还在范围内
但是最后一个bug卡了我整整20min，就是：
我发现2*n + 1不够，因为diff +- 2能到这个外面去，所以拓展为2 * (n + 2) + 1
结果any[n] = -1忘记改成any[n + 2] = -1了
这个极不起眼的小问题卡住了好久。
而且我发现，太多名称了，我不太能把所有名称都缓存在cache里，所以我搞定any的初始化后，any[n] = -1的n实际上已经被我大脑的cache移除了，所以这也导致debug非常艰难。

## 卡点

- 同一个 diff，更早的下标不一定支配更晚的：更早的下标可能因为区间外没有足够的 0 或 1 而无法交换。
- 实现有很多 off-by-one 和条件要斟酌。
- 数组从 2n+1 扩展为 2(n+2)+1 后，any[n] = -1 忘了改成 any[n + 2] = -1，卡了 20min；名字太多，改完初始化后大脑里已经丢了这个 n。

## 关键点

- 前缀差值 diff 配合哈希/数组，查找 diff、diff ± 2 对应的最早下标。
- 拆成三张表：无条件表、"前面有 0"表、"前面有 1"表，按区间外能否提供交换字符选择查询哪张表。
