## 复盘笔记

# 3891

## 题意

整数数组，若 nums[i] 严格大于左右两邻则下标 i 特殊（0 < i < n-1）。每次操作可把任一元素加 1。先最大化特殊下标数量，再最小化达到该数量的总操作数，求最小总操作数。约束：n ≤ 1e5，值 ≤ 1e9。

## 我的思考

我的思路是，ans0始终沿着奇数步骤走，
ans1为可以连续两个数不选择，
它只能从两个状态来：
1、preAns1
2、ans0
它也需要跳步来累加，所以choose是用来控制ans1的累加情况的。
不在乎奇偶性，每次反转。ans1当从ans0过来时（也就是ans1 < ans0）
这时候ans0可能处于奇，也可能是偶，但无论奇偶都让ans1下一步开始累加（也就是设置choose = ture），因为这样只可能让ans1偏大，而偏大时，如果错过了答案，下一轮又会触发ans0 < ans1。
也就是：ans0 是固定基准链，而 ans1 是一个按“选一个、跳一个”的节奏前进的候选链；当发现 ans0 < ans1 时，就直接让候选链从当前更便宜的 ans0 重新出发。至于这一刻发生在奇数步还是偶数步，我不管。

观察到如果是奇数长度，那么答案固定了。
偶数长度，那么可以在某个地方连续两位不选为波峰。
那我直接用ans0遍历，时刻维持奇数下标的收集处理，作为基线。
再用ans1，保留连续两位不选，并且独立控制收集，当发现基线更优时，放弃原始ans1，改为从更优的基线开始。
直觉上能锁定，最终答案一定是：
如果为奇数长度，形状固定。
如果是偶数长度，会在某个地方连续两个不选。（如果非要证明，也很简单：m=2k，要放 k 个互不相邻的 1，它们之间至少需要 k-1 个 0；总共只有 k 个 0，所以除去用于隔开 1 的 k-1 个零，只剩 1 个额外的 0。因此这个额外的 0 只能放在开头、结尾，或者某两个必要的隔离零旁边）
代码可以覆盖这些情况。

我觉得很简洁。
然后代码也忠实的反应了我的思路。
